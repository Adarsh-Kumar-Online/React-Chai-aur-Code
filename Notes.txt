    // WORKING:

        // HOW REACT WORKS:
            // 1. React is a JavaScript library used to build user interfaces (UI) using reusable components.
            // 2. Components are JavaScript functions that return JSX, a syntax that looks like HTML but is written inside JavaScript.
            // 3. Components can be imported into other components, forming a component tree, with App usually being the root component.
            // 4. ReactDOM connects React to the browser's actual DOM. createRoot() creates a React root inside the HTML element with id="root", and root.render(<App />) displays the App component there.
            // 5. React manages UI updates by comparing the new render output with the previous one and updating the necessary parts of the actual DOM. This is called reconciliation.
            // 6. JSX is transformed into JavaScript by the project's build tools before the browser executes it.

        // HOW VITE WORKS:
            // 1. Vite is a frontend build tool, NOT a replacement for React. React handles the UI, while Vite handles development and building.
            // 2. During development, npm run dev starts Vite's development server, which serves our app and supports fast updates through Hot Module Replacement (HMR).
            // 3. In a Vite project, index.html is the entry point. It loads the JavaScript entry file, usually src/main.jsx, through a <script type="module"> tag.
            // 4. main.jsx imports React, ReactDOM, App.jsx and other required files, then renders the App component into the root element in index.html.
            // 5. Vite processes JSX and other imported files during development, allowing us to see changes quickly without restarting the server in most cases.
            // 6. npm run build creates an optimized production build, usually inside the dist folder, containing the assets needed to deploy the website.

        // REACT + VITE WORKFLOW:
            // index.html -> main.jsx -> App.jsx -> Other components
            // index.html provides the root HTML element, main.jsx starts the React app,
            // App.jsx organizes the UI, and other components build individual parts of it.

        // IMPORTANT:
            // - React is a library; Vite is a build tool and development server.
            // - ReactDOM is the browser-specific package that lets React manage the DOM.
            // - npm installs packages and runs scripts defined in package.json.
            // - npx executes package commands without necessarily requiring a global installation.
            // - In Create React App, react-scripts manages the development server and build process.
            // - In Vite, index.html explicitly loads the JavaScript entry file.
            // - React uses a real DOM, not a separate virtual DOM that directly replaces the webpage.
            //   It calculates UI changes and applies the necessary updates to the real DOM.

        // 1. First, we created our own customRender() function that takes two arguments:
        //    reactElement (our custom object) and container (the root DOM element).
        //    It reads the object and manually creates an HTML element using document.createElement().

        // 2. We used reactElement.type to decide which HTML element to create, and
        //    domElement.innerHTML = reactElement.children to insert its content.

        // 3. Initially, we could set attributes like href and target individually using
        //    setAttribute(). But this would require writing separate lines for every attribute.
        //    So, we used a for...in loop to iterate over all properties inside reactElement.props

        // 4. We skipped the "children" property inside the loop because it represents the
        //    element's content, which we had already handled separately.

        // 5. Finally, we used container.appendChild(domElement) to insert the created element
        //    into the actual webpage. This helped us understand how a basic custom renderer works.

        // 6. Next, we created a custom React element as a normal JavaScript object containing
        //    type, props and children. Our customRender() could render it because we wrote the
        //    function to understand this particular object structure.

        // 7. We then tried passing the same custom object directly to React's root.render().
        //    It did not work because React expects a valid React node, not an arbitrary object
        //    with properties that we chose ourselves.

        // 8. To understand how React elements are created, we wrote an anchor element using JSX.
        //    JSX looks like HTML, but it is transformed into JavaScript by the build tools.
        //    The result is a valid React element that React can render.

        // 9. We also created the same anchor element using React.createElement(), passing:
        //    - "a" as the element type
        //    - An object containing href and target as its props
        //    - The link text and a variable as its children
        //    This creates a valid React element without writing JSX.

        // 10. We declared a variable and passed it as a child to React.createElement().
        //     The variable's value becomes part of the rendered link text. In JSX, we would

        //     rendering. Although calling MyApp() directly may work in simple cases, we should
        //     use <MyApp /> so React can manage the component correctly.

        //     component or React element on the webpage.
